`evo-subagent` 为 DeepSeek Harness 提供角色分工路由、项目级经验进化、陪伴人格与用户习惯。

它把稳定的 Agent 角色映射到已经注册的 provider/model，并为每个角色积累已验证命令与经验。1.0 版本进一步支持选择助手的相处方式，为不同工作区或对话定制各自的人格与交流偏好。

## 功能

- 通过同名 Markdown 绑定文件路由每个 `agent_key`。
- 创建子 Agent 前严格验证 provider/model 组合。
- 自动维护每个 Agent 的 `prefercmd.md` 与 `memory.md`。
- 按项目工作区隔离绑定和进化数据。
- 支持全新上下文的 `spawn` 和继承对话上下文的 `fork`。
- 没有绑定文件时保留 DSH 原生模型继承行为。
- 不保存 API Key、端点、凭据或 provider 定义。
- 已确认的协作习惯可选择全局共享、按工作区共享或按对话独立维护（需主动开启）。
- 使用四文件维护陪伴人格，支持五种预设与有边界的自主风格探索（需主动开启）。

## 安装

`1.0.0` 需要 DeepSeek Harness `0.2.1-rc.2`（支持范围：`^0.2.1-rc.2`）以及 Node.js `>=24.2.0`。仍使用 DSH `0.1.5-rc.3` 时，请安装插件 `0.7.0`。

```sh
dsh plugin add evo-subagent
```

## 快速开始

![在 DSH 中打开并管理 evo-subagent](assets/evo-subagent-tutorial.gif)

1. 打开 **左下角更多 → 设置 → 内置插件 → evo-subagent**，展开配置卡片。入口在设置内，不是主侧栏单独的“插件”页面。
2. 选择工作区并添加内置角色，或把自定义绑定放入该工作区的 `agents/` 目录。
3. 为每个自定义绑定选择已经注册的 provider/model 组合。
4. 展开 Agent，即可查看其 `prefercmd.md` 与 `memory.md` 进化文件。
5. 如需人格或习惯功能，展开 **陪伴人格** 或 **用户习惯**，选择适用范围与目标，再为该档案开启功能。

这段约 25 秒的教程使用 DSH `0.2.1-rc.2` 中的演示工作区；进入设置后会放大面板，方便阅读。演示中的 provider/model 名称仅作示例，不代表新增内置模型。

## Agent 绑定

在项目中创建 `agents/` 目录，每个角色对应一个 Markdown 文件。文件名即 `agent_key`。

```text
project/
├─ agents/
│  ├─ code-reviewer.md
│  └─ researcher.md
└─ .evo_subagent/
   └─ evolution/
```

每个绑定文件以严格的 front matter 开头：

```md
---
provider: deepseek-official
model: deepseek-v4-flash
---

# Code reviewer
下方可以添加可选的角色说明。
```

provider 和 model 必须已经注册，匹配区分大小写。

使用对应的 key 调用插件工具：

```json
{
  "agent_key": "code-reviewer",
  "description": "审查实现",
  "prompt": "报告正确性、安全性和测试覆盖问题。",
  "run_in_background": false
}
```

## 内置角色

插件包含三个模板：

| `agent_key` | 角色 |
| --- | --- |
| `code-reviewer` | 按严重程度输出代码审查结果 |
| `researcher` | 基于证据的研究与核查 |
| `wps-worker` | 办公文档制作 |

项目中存在同名绑定时，项目绑定优先于内置模板。

## 随包提供的 Agent Skill

安装插件后，以下三个兼容 DSH 的技能会注册到 DSH 技能列表。它们用于指导主 Agent，不会增加新的 Subagent 角色。

| Skill | 用途 |
| --- | --- |
| `/evo-route-doctor` | 诊断模型路由不符、继承路径或未注册的 provider/model。 |
| `/evo-memory-review` | 检查角色的 `prefercmd.md` 与 `memory.md`，整理过期或冲突的知识。 |
| `/evo-delegation-guide` | 选择已有角色并准备边界明确的委派任务。 |

DSH 需要启用技能注册服务和技能工具才能显示这些条目。项目内同名技能可覆盖随包技能。技能文件也随 npm 包保存在 `skills/` 下。

## 进化

每个项目的角色知识保存在：

```text
.evo_subagent/evolution/<agent_key>/prefercmd.md
.evo_subagent/evolution/<agent_key>/memory.md
```

- `prefercmd.md` 记录已经验证可用的命令。
- `memory.md` 记录可复用经验和需要避免的失败。

前台 Subagent 会接收一段有长度限制的知识上下文，并可通过以下格式返回新内容：

```md
[[EVOLUTION]]
prefercmd:
- pnpm test
memory:
- 不要在 CI 中使用 --force。
[[/EVOLUTION]]
```

条目会去重并限制数量。使用 `!` 前缀标记最高优先级，使用 `?` 标记可在上下文紧张时压缩的条目。

后台任务由 DSH 向父 Agent 发送完成通知。使用 `run_in_background: false` 可等待结果并保存返回的进化条目；取消前台调用时也会停止对应子代理。

旧 `.smart_subagent/evolution` 数据仍可只读回退，并会在下次保存时复制到新目录。

## 适用范围

**陪伴人格**与**用户习惯**两栏都可以单独选择**适用范围**：

| 范围 | 行为 |
| --- | --- |
| 所有工作区共享 | 当前 DSH 用户目录内的所有工作区、对话共用一份档案，保留原来的默认行为。 |
| 每个工作区独立 | 同一工作区内跨对话共享，不同工作区可以设置不同人格和习惯。 |
| 每个对话独立 | 每个工作区中的每个主对话分别维护自己的档案。 |

选择独立模式后，在下方选择要配置的工作区或对话，再调整其设置。对话列表来自 DSH 当前已打开的会话；要配置旧对话，先打开它再刷新。子代理沿用所属主对话的档案，单独分叉的主对话有自己的身份。无法识别工作区或会话时停止注入，不回退到全局档案。

切换范围不会复制或删除档案。原有全局数据保留，新对象默认关闭功能，需要单独配置；切回某个范围时恢复其已保存的设置。独立档案位于 `$DSH_HOME/evo-subagent/scopes/{workspace|conversation}/<目标哈希>/`，其中包含 `persona/`（仍为四文件）和／或 `user-habits.md`，不往项目仓库写入文件。`sharing.json` 维护两栏的范围选择和共用的后台用量账本；新建档案不会增加每日额度。

## 陪伴人格

进入 **更多 → 设置 → 内置插件 → evo-subagent → 陪伴人格**。独立模块 `evo-subagent/persona` **默认关闭**；查看设置不创建文件、不调用模型。开启前请确认接受额外的模型用量及摘录处理。

- **两种模式：** 固定预设（温和陪伴、理性沉稳、轻松幽默、直接利落、细致引导），或自主探索。探索模式从安全预设开始，偶尔在连续几轮中小幅试探一个表达维度，累计观察 60 轮后停止随机试探，之后仍可根据明确反馈调整。当前用户要求和 Agent 职责始终优先。
- **每份档案四个文件：** 全局模式位于 `$DSH_HOME/evo-subagent/persona/{core,user,relationship,evolution}.md`，默认用户目录为 `~/.dsh`；独立模式使用上方说明的目录。分别维护用户可编辑的人格原则、已确认喜好、已确认相处约定，以及近期观察、预算、风格版本和一次回滚快照。文件为包含可编辑 JSON 块的 Markdown，请保留文档头与 generation 字段。格式损坏时停止使用，不会静默重置。
- **自动循环：** 仅处理功能开启后的真实用户主对话，回答正常完成、前台空闲后独立观察。每个会话累计第十轮，用同一次调用复盘该会话近十条观察；不采集子代理、工具、运行时注入、思维链、取消的轮次或旧聊天。最多保留八个近期会话窗口；为使提交文件小于 128 KiB，必要时会更早淘汰旧窗口。
- **有边界的进化：** 温暖、幽默、详略、主动、直接程度是数值维度，不接受模型任意编写指令。每次最多调整两个维度、每个一步；需要同一场景至少两个不同轮次的明确用户引文支持且无相反信号。核心原则不自动修改，长期喜好和相处记忆需确认，沉默与客气不等于喜欢。这是提示词层面的适应，不是训练权重或真实情感。
- **内部硬约束：** 普通观察输出上限 256 token，第十轮合并复盘 768 token；输入分别限制 6,000／14,000 UTF-8 字节，人格注入最多 3,600 字节（字节上限不等于精确 token 数）。固定每日最多 120 次调用、预留 32,768 输出 token，以 UTC 日期结算；设置与 API 均不能修改，旧档案中的自定义预算不再生效。失败／取消的调用也保守占用预留预算。15 秒截止、最多八个排队任务、不自动重试，新前台工作会取消正在运行的观察；拥堵或预算不足时可能跳过观察。同一模型提供方的限流仍可能影响速度。日常设置不展示这些技术计数。
- **模型与隐私：** 默认跟随本轮已注册模型，旧档案中已固定的路由继续保留；高级 API 集成仍可提供注册模型组合，日常界面无需配置 provider/model。优先选择可用的非思考／低强度，而不继承主代理 high。观察器无工具，不把评估内容拼入聊天。有限的用户／回答摘录及候选引文会发送给该提供方并在本机保存；过滤明显密钥与引用／代码块，但不是完整的秘密检测器。认证设置中可暂停了解、关闭人格、忘记条目、清除未确认的了解或恢复上次风格；这些操作不会删除既有 DSH／提供方日志。

四文件提交检查点支持崩溃恢复、本机写锁和旧版本保护。同 generation 的手动 JSON 修改会被识别，旧投影在下次成功写入时从 `evolution.md` 恢复。直接编辑前请备份，不要混用不同版本的文件；崩溃遗留 `.lock` 时先停止写入进程，再检查清理。没有云同步、外部 CLI 自动注入、全局 `AGENTS.md` 修改或旧习惯档案的自动迁移；原有已确认习惯仍独立保留。关闭可选运行时上下文的 DSH 预设可能不会收到人格注入。

## 用户协作习惯

打开 **左下角更多 → 设置 → 内置插件 → evo-subagent → 用户习惯**，主动开启该功能。**默认关闭**，仅安装或查看不会创建习惯文件；也可以先手动准备已确认习惯，再开启应用。

安装包增加独立的 `evo-subagent/habits` 插件项，只依赖 DSH 的工具和提示词服务，不依赖子代理路由。同一个 DSH 运行时与用户目录的主代理、官方子代理和 evo 子代理按所选范围读取对应档案，无需先调用 `evo_subagent`。

全局模式的档案保存在项目仓库之外，独立模式使用上方说明的目录：

```text
$DSH_HOME/evo-subagent/user-habits.md
```

未设置 `DSH_HOME` 时，默认位于 `~/.dsh/evo-subagent/user-habits.md`。不同用户目录、Windows/WSL 安装和设备之间**不会自动共享或同步**。第一版仅适合一个用户独占的 DSH 服务，不是多人个性化系统；不会修改全局或项目 `AGENTS.md`。

- **一段通用摘要：** 只展示跨对话的语言、详略、语气、回答结构和证据偏好，不逐条列分类。称呼、昵称、角色扮演、临时情绪、本次任务和项目细节留在各自对话中，不作为全局习惯。
- **整体更新：** 助手通过 `evo_user_habits` 引用真实用户原话，提出有通用依据的偏好；有效候选合并成一份新摘要，用户可整体修改、采用或暂不采用。子代理只能读取共享摘要，不能提议修改。
- **管理：** 整体编辑摘要、清空文字以忘记当前应用的偏好、确认合并更新、暂停建议或关闭注入。旧的具体记录保留在原文件中，但不再展示或全局注入；人格记忆同样使用这一范围过滤，避免旧昵称从另一条路径重新进入其他对话。
- **边界：** 习惯作为低优先级用户上下文，不是执行权限、项目知识、人格判断或迎合用户观点的理由；当前明确要求和适用的项目规则优先。不扫描旧会话，不另调模型分析行为；是否提出新建议仍取决于当前助手调用工具。
- **隐私：** 只有已确认的通用摘要进入模型上下文。依据短句保留在本地档案和既有对话／工具日志中，不再在界面铺成列表。编辑或清空应用摘要不会删除历史依据、DSH 日志或提供方记录。不增加云同步或遥测。

摘要最多 960 字符；内部通用记录保留 12 条已确认／20 条候选、每条 240 字符的上限。摘要合并与常见局部范围过滤不额外调用模型，是保守规则而非完美的语义分类。Markdown 仍是数据源，未识别或损坏内容不会被静默覆盖。写入采用版本校验、本地锁和原子替换；若崩溃遗留 `.lock`，应先停止写入，再检查处理。

支持开启运行时上下文的常规 DSH 预设；关闭可选运行时上下文的预设，以及独立的 Codex/Claude Code 外部进程，不保证自动收到该档案。该功能不改变权限、模型或角色提示词。

## 工作区管理

插件设置卡片按项目分组 Agent，并支持：

- 展开或折叠工作区 Agent 列表；
- 编辑自定义绑定的已注册 provider/model 路由；
- 将内置角色模板复制到指定工作区；
- 绑定一个工作区根目录的 `AGENTS.md` 作为 Main agent；
- 查看和编辑每个 Agent 的进化文件。

Main agent 的进化数据位于 `.evo_subagent/evolution/main/`。绑定或解绑只会修改 `AGENTS.md` 中由插件管理的指令区块。

## 工具字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `agent_key` | 是 | 不含 `.md` 的绑定文件名。 |
| `description` | 是 | 简短任务名称。 |
| `prompt` | 是 | 发送给子 Agent 的完整任务。 |
| `run_in_background` | 否 | 默认 `true`；设为 `false` 时可收集进化输出。 |

## 路由流程

1. 安全解析 `<agent_key>.md`。
2. 读取 fenced front matter 中的 `provider` 和 `model`。
3. 在实时模型注册表中验证两个值。
4. 通过所选 `spawn` 或 `fork` provider 创建子 Agent。

无效绑定会在创建子 Agent 前失败。绑定缺失且没有同名内置模板时，保留 DSH 原生继承行为。

## 开发

